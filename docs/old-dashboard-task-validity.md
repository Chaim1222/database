## התיקון והסיבה לטבלת האימות

ב־V1, `match.py` יכול לקבוע `wikipedia_id` לפי כותרת בלבד, בלי לקרוא את התבנית. `template_referenced_title IS NULL` אינו הוכחה שנקראה תבנית ונפתר שיוכה. לכן אין לסנן את הדוח על סמך שני השדות האלה בלבד: שם ישן שנתפס מחדש עלול להסתיר העברה אמיתית.

המיגרציה `migrations/20261006205515_old_dashboard_task_validity.sql` מוסיפה טבלת אימות קטנה `maintenance_move_sources`, בלי מפתח זר לטבלאות המראה המוחלפות. היא מיועדת רק למועמדי ההעברה, ולא לכל מאות אלפי הערכים.

`scripts/check_move_sources.py` קורא את תבנית המיון הנוכחית של המועמדים, מאמת שהגרסה שנקראה תואמת לגרסה המפוענחת במסד, ושואל לאיזה דף ויקיפדיה שייכת גרסת המקור. הוכחה נשמרת רק אם הדף חי במרחב הראשי, אינו הפניה, ושם התבנית מתאים לשמו הנוכחי. תשובה חסרה אינה הוכחה; תשובה חסרה מוויקיפדיה מכשילה את האימות. מידע שלא אומת נשאר מועמד לבדיקה.

הדוח מסתיר פגיעה בשם היסטורי רק כשיש הוכחה תקפה לזהות אחרת, או שיוך ידני מפורש למזהה אחר. התאמה אוטומטית לפי כותרת אינה מסתירה. ההוכחה מתבטלת מבחינת הדוח אם גרסת המכלול או גרסת המקור השתנתה, או שהפענוח אינו מעודכן. ברענון הבא כל המועמדים נבדקים שוב, גם אלה שהוסתרו.

`report_wikipedia_move_candidates` שומר את מסלולי הכותרת והתבנית הקיימים, לפני סינון האימות. `report_wikipedia_moves` ממשיך להחזיר את אותן עמודות, שורה אחת לערך וקדימות לכותרת. אין שינוי בנוסחי הממשק, בנרמול, בהיסטוריית ההעברות או בקישורי המראה.

`report_rev_tasks` אינו מציג ממצא שמספר גרסת המקור שלו שונה מהמספר הנוכחי במסד (`IS NOT DISTINCT FROM`, כולל NULL). הממצא עצמו אינו נמחק. הבדיקה החוזרת הקיימת תקבע אם עדיין יש בעיה; החלפת המספר אינה מסומנת כ"תקין".

השלב החדש נוסף **רק** ל־`maintenance_refresh.yml`, אחרי הדלתא, ההתאמה ועדכון גרסת התבנית. הוא מסומן `continue-on-error: true`: כשל API או מיגרציה שטרם הוחלה נראים ביומן של השלב, אך אינם עוצרים את בדיקת הגרסאות החוזרת, הניקוי ואימות הנעילות, ואינם כשלעצמם מכשילים את הרענון או פותחים Issue. מועמד ללא הוכחה תקפה נשאר גלוי. תזמונים והעדכון השעתי לא שונו. אימות חדש נדרש לאחר שינוי גרסה; עד לרענון, מועמד שלא הוכרע עשוי להופיע שוב באופן שמרני.

## אימות לפני פריסה

- בדיקות Python של תוצאות חיוביות, גרסה שהתיישנה, שם ישן שנתפס מחדש, דף נעול/חסר, הפניה/טיוטה, תשובה חסרה וזהות סותרת.
- בדיקות PostgreSQL מבודד (PGlite), המריצות את קובץ המיגרציה עצמו: משימות שווא מול משימות אמיתיות, שיוכים ידניים, NULL, קדימות ושורה אחת, החלה חוזרת, ביטול, קריאת anon/authenticated וחסימת כתיבה מהם. כל התצוגות `security_invoker`, הטבלה עם RLS; כתיבה ל־service_role בלבד.
- הדמיה בקריאה בלבד על המסד החי, באמצעות הזהויות שאומתו מול האתרים: 16 מועמדים נעשים 2. שתי השורות שנותרות הן ההיסטוריה וישראל כהן. הסרת ישראל כהן אחרי עדכון הדלתא עדיין אינה מאומתת: לא הופעלה ריצה שכותבת למסד.
- פקודות הבדיקה:
  `python -m unittest discover -s scripts/tests`
  `node --test gadget/tests/*.test.js`
  `PGLITE_PACKAGE_JSON=/path/to/package.json node scripts/tests/test_dashboard_task_validity_sql.mjs`

תוצאות הבדיקות: 174 בדיקות Python, 50 בדיקות הגאדג'ט ו־26 בדיקות SQL/הרשאות/ביטול עברו. בדיקה נוספת מול ה־API החי אימתה 15 גרסאות מקור מתוך 16 מועמדים באמצעות הקוד החדש; בישראל כהן הזהות היא של הדף שהדוח מציע, ולכן הוא אינו מוסתר באמצעות האימות. ההיסטוריה ללא פענוח עדכני במסד ולכן אינה מוסתרת. כל 14 הזהויות האחרות תואמות לדף אחר ומסירות את משימות השווא.
