# דשבורד משותף V1/V2

זרימה: כתובת הדף ובורר V1/V2 → חיבור קבוע למסד ולסכמה → בדיקת הרשאות → דוחות וסינון → פירוט לפי דרישה → פעולת ייבוא באתר או כתיבה למסד שנבחר.

`gadget/gadget-searchHelperDashboard.js` הוא הממשק המשותף. העיצוב, הייבוא ופירוט סינון המילים משתמשים בקוד V1 הקיים. לשונית עדכון/מיזוג אינה נטענת, בהתאם להחלטת חיים להוציא אותה מההיקף.

הדף `מיוחד:דף ריק/database` משתמש כברירת מחדל ב־V1. הדף `מיוחד:דף ריק/database-v2` משתמש ב־V2. הפרמטר `mchlDb=v1` או `mchlDb=v2` גובר על ברירת המחדל. החלפת המסד בבורר טוענת מחדש את הדף. טעינה כפולה של הסקריפט אינה יוצרת ממשק כפול.

| פעולה | V1 | V2 |
|---|---|---|
| דוחות | public.report_* | api.report_* |
| בדיקת מנהל | is_manual_match_admin | is_admin |
| שיוך ידני | manual_matches | set_manual_link |

מפתחות anon ציבוריים בלבד. הטוקן נשמר בנפרד לכל פרויקט; V1 שומר על מפתח הסשן הקיים. מוני הדוחות נשמרים בנפרד. כתיבות V2 משתמשות ב־RPC הקיימים ובבדיקות המנהל שלהם. אין שינוי בכללי ההתאמה, הכיסוי או הסינון. ייבוא ותיקון תבנית ממשיכים לפתוח את המנגנון הקיים באתר.

## תלות ופריסה

יש לשלב תחילה את ענף `fix/align-production-20261008`, שמכיל את `0037_rev_scope_custom_plan.sql`. בדיקת השילוב המקומית אישרה שהסכמה הממוזגת תואמת למיגרציות המשולבות; CI צריך לאמת זאת גם ב־PostgreSQL רגיל. לפני טעינת הממשק מול V2 יש להחיל `db/migrations/0038_shared_dashboard_compat.sql` מהמאגר database_V2 בתהליך המיגרציות הרגיל. היא מוסיפה סיכום סינון, משמרת הקשר למשוב ומתקנת מזהים בדוחות נעילות וגרסאות. אין להפעיל workflow של סריקות כחלק מהפריסה הזו ללא החלטה נפרדת.

לאחר החלת המיגרציה: מעדכנים את דף הסקריפט שבו נטען הגאדג'ט הקיים ואת דף `משתמש:בוט גאון הירדן/dashboard.css` מה־CSS הקיים. יש להחליף את הטעינה של הדשבורד הנפרד בדף database-v2 בטעינה של אותו סקריפט משותף; אין לטעון את שניהם ביחד. לא בוצעו שינויים באתר או במסדים החיים במסגרת ה־PR.

## נתונים חסרים ומגבלות

בבדיקה החיה לפני השינוי לא היו ב־V2 תוצאות סריקת תוכן. הממשק פותח ב־V2 את כל החסרים, ולא מסנן מראש ל״נקי״. `not_scanned` מוצג כלא נסרק ו־`stale` כתוצאה ישנה. רק מצב scanned נכלל במסנן נקי. היעדר מידע על תמונות/הפניות אינו מוצג כאילו הבדיקה התקיימה.

סרגל הכיסוי התואמים/משימות/חסרים של V1 מוסתר ב־V2: למודל V2 אין אותו מונה תואמים, ולא נגזר מונה חדש באמצעות כלל התאמה חדש. ספירות גודל המראות נלקחות מ־v_counts. גרף ההיסטוריה הטקסטואלי מהממשק הנפרד של V2 אינו מועתק לממשק המשותף בשינוי הזה.

## אימות

`node --test gadget/tests/*.test.js` בודק גם בחירת מסד, סכמה, שיוך, משוב עם הקשר, ביטול והחרגה. בדיקות SQL ב־V2 מכסות את תפקידי anon/authenticated, הפרדת מזהי נעילות, סיכום סריקות, שיוך כפול, כיסוי תבנית והרשאות משוב. בדיקת ממשק מקומית משתמשת בתשובות מדומות; היא אינה בדיקת כתיבה למסד חי.

## סקירת השפעה ואימות מורחב — 9.10.2026

נבדקו צרכני הדוחות, מיון ועימוד, ייצוא, פרטי הסינון, הרשאות, התחברות וחידוש טוקן, שיוך ידני והחרגה. ב־V2 נבדקו גם הדשבורד העצמאי והסורק המשותף; הם שומרים על הקריאות הקיימות. לא שונו כללי התאמה או הרשאות במסד.

הממצאים שתוקנו בסקירה:

- שכבת התאימות שומרת גם על החרגת locked_create, כפי שנקבע ב־0017. בדיקת t14 חשפה השמטה בהכנה הראשונית; היא תוקנה, נוספה בדיקה מפורשת ב־t32 וכל 30 קובצי ה־SQL עברו מחדש.
- קבוצת התחזוקה ב־V1 בוחרת לשונית שמותרת במסד הנוכחי; היא אינה פונה עוד לדוח המערכת של V2 כברירת מחדל.
- מיון יציב נבנה ממפתחות הדוח בפועל. מצב המערכת ממוין לפי kind, התאמות הרב/רבי לפי שני מזהים, ונעילות לפי אתר/מזהה/כותרת. אותו סדר משמש עימוד וייצוא.
- ייצוא נעילות V2 כולל את האתר ומזהה המכלול, גם כאשר לשני האתרים אותו מספר דף.
- כשל בקריאת משוב מוצג כשגיאה; 401 מפעיל חידוש טוקן וניסיון חוזר. כשל אינו מוצג כ״אין סימונים״.
- קריאת המשוב ב־V1 מסוננת למשתמש המחובר. ב־V2 ההגבלה כבר נאכפת ב־view. טוקן ישן נתמך באמצעות sub, והתחברות חדשה שומרת גם user_id. אין שינוי במדיניות הרשאות.
- תוויות פעולה ריקות נשמרות ריקות גם בנייד, במקום להציג import_action ו־expand.

### שחזור

ללא תלות בדפדפן: `node --test gadget/tests/*.test.js word-filter/tests/*.test.js`.

בדיקות הדפדפן: `node gadget/tests/dashboardBrowser.cjs`, בסביבה שבה Playwright ו־Chromium מותקנים. אפשר לציין `CHROMIUM_EXECUTABLE=/path/to/chromium`. המשתנה `DASHBOARD_SCREENSHOTS=/existing/directory` שומר צילומי מחשב ונייד. הבדיקה חוסמת את כל הרשת באמצעות fixtures ואינה נוגעת בייצור. בדיקת ה־DOM הזמנית הוחלפה בבדיקת הדפדפן המלאה כדי להימנע מכפילות.

### מה עדיין לא אומת

- CI של GitHub ו־db/run_tests.sh על PostgreSQL רגיל: הניסיון המקומי נעצר ב־`psql: command not found`. סביבת הבדיקה תומכת רק בזהות מערכת root, ולכן התקנת Postgres הרגילה לא הושלמה. בדיקות PGlite אינן מוצגות כהרצת הסקריפט הזה.
- כתיבות אמת במסדים או באתר ובדיקת הממשק בתוך מעטפת האתר החי: לא בוצעו. כל הפעולות בדפדפן השתמשו בתשובות מדומות; בייצור נעשו קריאות בלבד.
- 0038 טרם הוחלה. לכן פריסת הממשק מול V2 עדיין תלויה במיגרציה ובאימות שאחריה.
- הענפים הועלו ל־GitHub לאחר אישור. אין עדיין PR או תוצאת CI.

הדשבורד העצמאי ב־V2 משתמש ב־v_missing וב־mech_redirect=eq.false. תצוגה זו אינה משתנה ב־0038. הבדיקה t32 מאמתת שערך שלא נבדק נכלל הן במסנן הישן והן במסנן not.is.true של הדשבורד המשותף.
אימות השילוב: 30 בדיקות SQL עברו בענף הדשבורד בנפרד; בשילוב מקומי של 0037 מענף היישור ולאחריה 0038 עברו 31 בדיקות, לרבות בדיקת rev_scope ובדיקת הדשבורד. הבדיקות רצו ב־PGlite, לא ב־CI. מספור המיגרציה אינו משנה כשלעצמו את schema.sql, שאינו כולל את רשומות טבלת הגרסאות.

נוסף workflow לבקשות מיזוג שמשנות gadget/word-filter: בדיקות Node ו־Chromium עם Playwright 1.62.1, ללא secrets ובאמצעות רשת מדומה.
